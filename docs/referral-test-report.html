Coverage gaps and risk notes

Not a live end-to-end certification. Tests use fake Firebase storage and mocked Razorpay data. Live credentials, provider webhook delivery/signature rejection, deployed Firestore indexes/rules, and production account/payment state were not exercised.
  • No real browser automation verified the responsive referral page, Google popup flow, clipboard permissions, native share sheet, or posting behavior on social networks. Facebook does not let third-party sites prefill post text; this test verifies the supported copy-and-open flow, not the contents of a Facebook composer.
  • Admin referral search/export/details and all mutations (reject, reverse, adjustment, code disable/enable), including their authorization, missing-reason, and malformed-input cases, are not comprehensively covered here. The high-volume approval and audit path is covered.
  • Pagination cursor tampering, malformed limits/codes, simultaneous registration/webhook races, first-touch replacement/expiry boundaries, webhook signature failures, and additional out-of-order reversal/payment permutations need dedicated tests.
  • Source-pattern assertions confirm parts of the UI and Firestore rules text; they are not substitutes for browser behavior tests or emulator/deployed rules evaluation.

Recommended follow-up: add Admin route authorization/mutation tests and adversarial cursor/input tests, then run Firebase Emulator and Razorpay test-mode browser/webhook checks before production rollout.
